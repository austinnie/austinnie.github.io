## 痛点：一个具体的麻烦

我们组 3 个人，主要做行业访谈类内容。每周录一条 90 分钟到 2 小时的长视频，然后要切成 3 到 5 条竖屏短视频发抖音、小红书、B 站。

问题不在剪辑本身，在于**前后那堆杂活**：

- 在时间线上找"金句"和"节奏好的段落"，一条视频翻来覆去看三遍，40 分钟起步；
- 手动给每条短视频打轴、校对字幕，错别字、断句不自然，再来 30 分钟；
- 截一张能当封面的帧，调一下尺寸比例，10 分钟；
- 写标题、写 80 字的发布文案、打标签，15 分钟；
- 最后导出 mp4、登录各平台后台上传，又 10 分钟。

一条短视频全流程 1.5 到 2 小时。一周出 10 条，光这套流程就吃掉两到三天。剪辑本身可能才占 20% 的时间，剩下 80% 全在重复劳动里。

## 之前我们是怎么做的

说实话，流程就五步，笨但稳定：

1. **导入长视频到剪映/CapCut**，拖到时间线。
2. **手动找剪辑点**，靠反复拖动播放头、记时间码。"这段不错"→ 记下来 → 下一段。
3. **手动加字幕**，用剪映自带的自动识别跑一版，然后逐句校对（自动识别在方言、专业术语上错得离谱）。
4. **手动出封面和文案**，截图→套模板→写标题→复制粘贴到发布框。
5. **导出，手动上传**，每个平台单独操作一次。

没有哪一步有技术含量，但每一步都得人盯着。最崩溃的是第 2 步和第 3 步：你明明知道"这段话是精华"，但定位到秒、再剪出来、再对字幕，来回折腾半小时，效率极低。

## 为什么最后选了这个项目

当时手上其实在比两个替代：

- **OpusClip（SaaS）**：功能确实全，上传一条视频它自动切条、出字幕、出封面。但视频要传到人家服务器，按量/按月收费，而且我们不想把未发布的内部访谈内容放在第三方平台上。
- **继续手动 + 剪映自动字幕**：免费、本地，但"找剪辑点"和"写文案"这两步还是人肉，省不了多少时间。

最后选了 [zhouxiaoka/autoclip](https://github.com/zhouxiaoka/autoclip)，原因很朴素：

1. **本地跑**，视频不出机器，MIT 协议，零订阅；
2. 桌面应用形态（Tauri 壳），不需要自己搭环境；
3. 一条命令/一个按钮把"剪片→字幕→封面→文案"串完，不是半自动；
4. 支持直接输出适配抖音、小红书、TikTok、Reels、YouTube Shorts 的规格。

取舍是：它的"智能剪辑"依赖本地模型，对特别长（3 小时以上）或画质很差的源视频，效果不如人工精细；但对我们 1-2 小时的访谈/播客源文件，够用。

## 关键步骤

整条流程其实就四步，我按实际操作顺序写：

**① 启动 AutoClip，指定源视频（或丢一个链接）**

桌面端打开后，拖入本地 `.mp4` / `.mov`，或者贴一个 YouTube / 播客链接。按文档描述，它会自动拉流或读取本地文件。这一步唯一要操心的是确认源文件时长在 30 min - 3 h 之间（我们实测 90 min 最舒服）。

**② 选"剪辑策略"，跑自动剪辑**

默认是"高信息密度段落优先"。伪代码大概是：

```
autoclip clip --input interview_0412.mp4 \
  --strategy density \
  --output-format vertical_9x16 \
  --max-clips 5
```

它会在后台调 Whisper（本地）做语音转写，再用 LLM 挑"值得单独成条"的段落，输出 N 条竖屏片段。这一步耗时和源视频长度正相关，README 里没给具体分钟数，我跑一条 90 min 的体感是十几到二十几分钟，可以去泡杯咖啡。

**③ 自动出字幕、封面、文案**

剪辑跑完后，同一次任务里它会：
- 把转写文本对齐到每条片段，烧录或挂软字幕；
- 从片段中抽一帧做封面（可指定风格）；
- 生成一条标题 + 一段 60-100 字的发布文案 + 标签。

这一步不需要额外操作，跟第 ② 步是同一个 pipeline 里跑完的。

**④ 导出 / 一键发布**

按文档描述，导出是本地 mp4 + 配套文件包；部分平台支持通过内置的 MCP server 让 AI agent 直接调用发布接口。我们目前还是手动把文件拖到各平台后台，但封面和文案已经复制粘贴就完事了。

## 跑完之后

按项目 README 和文档的描述，一条 90 分钟的访谈视频，AutoClip 可以一次性产出：若干条竖屏剪辑（条数可控）、每条对应的时间对齐字幕、一张封面图、一段发布文案和标签。输出规格适配抖音、小红书、TikTok、Instagram Reels 和 YouTube Shorts。

我没有做严格的计时对比（因为"手动"那条线本身波动很大，今天状态好 1 小时、状态差 2 小时），所以不编"省了 X 小时"这种数字。但流程上确实从 5 步人肉压缩到了"点一下、等十几分钟、检查输出"，最费脑力的"找剪辑点"和"写文案"被模型代劳了。

一个实际感受：自动字幕在普通话、语速正常的访谈上准确率可以接受，但遇到我们嘉宾带点口音或说英文术语，还是得逐句过一遍改几个字。封面和文案属于"能用但需要人工润色再发"的水平，不是发完就完事。

## 适合谁 / 不适合谁

**比较适合：**
- 1-5 人小团队，每周稳定产出 3 条以上短视频，源视频是访谈、播客、课程、游戏录像这类"说话为主"的内容；
- 不想把未公开内容上传到 SaaS 平台，有数据合规顾虑；
- 接受"AI 初剪 + 人工微调"的节奏，不指望全自动零人工。

**不太适合 / 需要再想想：**
- 源视频是高度视觉驱动的内容（vlog、旅行、MV），"信息密度"策略切不出你要的画面；
- 对剪辑节奏、转场、BGM 有强审美要求，AutoClip 输出的是"功能正确"的片段，不是"导演级"的片子；
- 机器配置偏低（README 没写最低硬件要求，但本地跑 Whisper + LLM，建议 16 GB 内存起步，有独显更好），跑起来会很慢甚至跑不动；
- 需要团队协作 / 审批流 / 多角色分工，它目前是桌面端单人工具。

> 本文基于 zhouxiaoka/autoclip 的 README 与公开信息整理，未做完整实测，关键步骤仅供参考。
