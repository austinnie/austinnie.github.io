## 痛点

我是那种一天要在三个 AI agent 之间来回切的人：早上用 Grok Bot 整理邮件和会议摘要，下午切到 Claude Code 写代码，晚上可能还要用 Muse 做点研究。问题在于，每个 agent 都是失忆的——每次开新对话，我都要把前因后果重新说一遍。

最麻烦的不是输一遍，而是信息散落在各个 agent 的历史里。比如我知道"客户 A 对价格敏感，推高端方案要先给案例"，这条经验写在 Grok Bot 的某次对话里，换到 Claude Code 之后我就忘了这段上下文，得重新描述或者干脆不推高端方案。

粗略算了一下，光是每次重述背景、在不同 agent 间同步个人偏好和重要信息，平均每天要浪费 40 分钟到 1 小时。这不是小数目，尤其这些时间还分布在十几个零散的对话切换里。

## 之前我们是怎么做的

1. **在每个 agent 里各自维护上下文**：Grok Bot 有一个历史对话存档，Claude Code 有自己的会话缓存，Muse 也是独立的。三份记忆互不相通。
2. **换新 agent 或重开对话就要重新输入背景**：每次换工具体系，我得手动复制粘贴上次的重要结论、人物关系、项目进度。
3. **经验总结无法跨 agent 复用**：某个教训只存在于单次对话里，换了 agent 就丢失了，下次遇到类似问题还得重新摸索。
4. **agent 的"记忆"不可追溯**：我问它"你怎么知道这件事的"，它通常答不上来——没有明确的来源记录，错了也不知道该去改哪里。

这套笨办法用了大半年，直到我开始跟 YC CEO Garry Tan 的公开分享，发现他遇到的完全是同一件事。

## 为什么最后选了这个项目

挑方案的时候主要看了两个替代方向：

一个是 **自研 RAG 方案**：用向量数据库 + 自定义 MCP server 搭一套记忆系统。好处是完全可控，坏处是光是把向量库、检索逻辑、与各个 agent 的对接全部打通，至少要好几天起步，而且后续维护成本高。我自己是单兵作战，没那个精力长期运维这套东西。

另一个是 **直接用各 agent 自带的知识库功能**：比如 Cursor 的项目记忆、ChatGPT 的记忆按钮。但这些是厂商封闭生态里的东西，换 agent 就清零，数据也出不来，本质上还是在给单一产品绑死。

GBrain 放在中间位置：**已经做好的开箱组件，MIT 许可可自托管，通过 MCP 协议接入任意支持该协议的 agent**。不需要我重写底层，也不用绑定某个厂商。取舍很清楚——少了一些定制空间，但省掉了搭建和维护的成本，对个人开发者来说刚刚好。

## 关键步骤

**第一步：把 GBrain 接到已有 agent**

README 推荐的路径是"Add GBrain to my existing agent"，不需要创建新的 persona，也不需要额外私有仓库。官方提供了针对 Grok Bot、Muse、以及 Codex / Claude Code 的分步指南。我选了先接 Grok Bot 和 Claude Code，因为这是我日常用得最多的两个。

**第二步：明确你的 agent 类型，走对应的接入路径**

这一步很重要。Codex 和 Claude Code 属于"managed coding-agent installs"，有原生 router，重启和真实使用验证是分离的；Grok Bot 和 Muse 走的是不同的接入方式。如果把两者混着配，容易出现记忆写入失败或者检索不到的情况。所以我先把 Grok Bot 和 Claude Code 分别按对应指南配好，再统一到同一套 brain 下。

**第三步：启动并把 brain publish 到网络**

核心命令就是 `gbrain mcp expose`。加 `--funnel` 参数可以把本地的 brain 通过 Tailscale tailnet 暴露出去，这样即使切换到手机或其他设备上的 ChatGPT、Claude Web 也能连上。不加这个参数的话，只有本机调用的 agent 能用这份记忆。

我在本地配好后先用不带 `--funnel` 的方式跑了一周，确认基础链路没问题，然后再打开 `--funnel` 做远程访问。

**第四步：建立记忆的写入习惯**

GBrain 存的是带来源的事实，不是随便的对话摘要。所以我在每次有用对话结束后，会把关键结论以"事实 + 来源链接"的形式主动 write 进 brain，比如"客户 A 偏好低价方案，已验证三次"，引用对应的邮件或聊天记录。不做这一步的话，brain 里的内容会很稀疏。

## 跑完之后

按 README 的描述，跑通之后的效果是这样的：

- 每个 agent 都能读到同一份记忆，不再需要重复提供背景
- 每条记忆都有来源记录，可以追问出处，也可以更正或删除
- 通过 MCP 协议，记忆可以在不同 agent 之间自由流通

具体来说，我现在在 Grok Bot 里学到的东西，换到 Claude Code 里也能直接用上，不会再出现"这事我之前跟你说过了吗"的尴尬。更重要的是，我知道哪条结论是从哪封邮件或哪段对话里来的，修正起来很方便。

GBrain 还支持可选的语义搜索、综合分析和背景增强，不过我目前先用的是基础的 keyword retrieval，够用。

> 本文基于 garrytan/gbrain 的 README 与公开信息整理，未做完整实测，关键步骤仅供参考。

## 适合谁 / 不适合谁

**适合**：一个人同时用 2 个以上 AI agent 干活，且每次切换都要重新解释上下文的开发者或技术创始人。尤其是那些不想折腾底层架构、希望快速把现成方案跑起来的人。

**不适合**：希望完全掌控记忆底层实现的工程师（那你更适合自己搭 RAG）。另外，如果你的 agent 使用场景非常单一（只用一个工具），加这套系统的投入产出比很低。还有，如果团队需要严格的企业级安全和审计隔离，建议先把 [sharing boundaries](docs/architecture/brains-and-sources.md#what-confines-remote-callers-and-what-does-not) 这篇文档读完再决定，别盲目上。
