## 痛点

做红队侦察的时候，我拿到一个嫌疑人用户名 user123，需要在几十个甚至上百个社交平台、论坛、技术社区上搜他有没有注册。按传统做法，我得手动打开浏览器，一个个站点去试——GitHub、Twitter、Reddit、Instagram、TikTok、Discord、Telegram、各种小众论坛……每个站点开搜索框，敲进去，看有没有匹配结果，然后记到笔记里。整个过程非常机械重复，而且人总会漏掉几个站，尤其是那种冷门平台，忘了就等于漏网之鱼。有时候光扫一遍就得两三个小时，还不敢保证没遗漏。


![illustration](/images/illustration_03.png)

## 之前我们是怎么做的

- 手动打开浏览器逐一访问各社交平台
- 在每个平台搜索框输入目标用户名
- 记录找到的账号链接至笔记
- 重复操作覆盖多个站点
- 整理汇总结果并去重

每一步都是纯体力活，中间还不能分心——一旦走神就漏站点。后来我们尝试用 Excel 做个表，把站点一行行列出来，打完勾再往下走，好歹能系统化一点，但本质还是手工劳动，只是多了张表而已。

## 为什么最后选了这个项目

我们之前也看过两个替代方案：一个是 maltego，图形化界面很强大，适合团队深度侦查，但学习成本不低，而且免费版功能受限，个人或小团队用起来有点大材小用；另一个是某款商业 OSINT 工具，集成度高，但授权费贵，对独立从业者不太友好。sherlock-project/sherlock 的优势在于轻量、免费、纯命令行，装完就能跑，不需要 GUI，也不需要配置复杂的环境。它专门针对用户名跨站扫描这件事做，400+ 站点的支持量目前看起来够用，输出格式还能直接导出 CSV/XLSX，后续处理方便。考虑到我们主要是快速出结果而不是做长期平台建设，最终选了它。

## 关键步骤

**第一步：安装。** 官方推荐用 `pipx install sherlock-project`，也可以用 Docker 或 `dnf`。我用的是 pipx，装完验证一下版本，确保没问题。

**第二步：准备目标列表。** README 显示支持多用户名批量查询，所以我先把要查的几个候选用户名写在文件里，或者直接命令行传参，比如 `sherlock user123 user456`。如果要批量导入，可以借助 JSON 配置文件，但这个得看具体需求。

**第三步：执行扫描。** 基础命令是 `sherlock --csv --xlsx --folderoutput ./results user123`。加 `--csv` 和 `--xlsx` 是为了让结果输出为结构化表格，方便后续筛选；`--folderoutput` 指定输出目录，避免文件散落在各处。这里注意，按文档描述，默认会跳过一些 NSFW 站点，如果发现站点缺失可以用 `--nsfw` 参数开启。

**第四步：检查输出。** 扫描结束后，结果会生成在指定文件夹下，文件名对应用户名，如 `user123.csv`、`user123.xlsx`。CSV/XLSX 里的每一行对应一个站点、状态码、URL，可以直接进 Excel 筛一遍已找到和未找到的，效率比看文本输出高很多。

**第五步：复用与扩展。** 如果发现某个站点响应异常或被屏蔽，可以用 `--site SITE_NAME` 单独测试，或者用 `--proxy PROXY_URL` 换代理重试。这些选项 README 都有说明，按场景组合即可。

## 跑完之后

按项目文档描述，一键扫描覆盖 400+ 社交网络，结果支持导出为文本/CSV/XLSX 三种格式。实际跑下来，单个用户名的扫描速度确实比手动快很多，输出也是结构化的，不用再一条条复制粘贴。不过 README 里也没说具体耗时数字，所以我不敢编"从 3 小时压到 5 分钟"这种话，只能说体感上流程顺畅了。另外，站点的覆盖率取决于项目本身的更新维护情况，一些冷门或新增的站点可能不在默认列表中，需要关注项目是否有新 PR 补充。

## 适合谁 / 不适合谁

适合：渗透测试师、OSINT 研究员、安全工程师，尤其是一线做红队侦察、CTI 调查的人，需要快速批量验证用户名的场景。独立从业者或小团队也能低成本上手。

不适合：需要深度分析账号内容（比如发帖历史、好友关系）的研究者，sherlock 只管"有没有这个账号"，不管账号本身的内容；另外如果你想要图形化界面、拖拽式操作，这个项目命令行为主，可能不合胃口。还有依赖 ParrotOS 或 Ubuntu 24.04 的用户要注意，README 明确提示第三方包可能有问题，建议用 pipx/Docker/pip 方式安装。
